# Architecture Spec 독립 리뷰 기준

리뷰 자료는 Product Spec과 Architecture Spec 두 문서다. Product Spec은 요구사항 기준이고 Architecture Spec이 리뷰 대상이다. 다른 파일이나 외부 자료를 읽지 않는다.

다음의 구체적인 결함만 확인한다.

- Product의 핵심 요구사항과 수용 조건이 Architecture에 빠졌거나 두 Spec이 모순되는지.
- Domain의 Entity와 Value Object, 필수 Aggregate와 root, application service, BC의 역할과 관계가 명확하고 업무 규칙의 책임이 일관되는지.
- 핵심 동작과 데이터, 저장·조회 등 요구사항 구현에 필요한 설계가 빠졌는지.
- 변경되는 핵심 업무 규칙의 테스트 사례가 조건과 기대 업무 결과를 설명하는지.

스펙에 적힌 설계만 판단한다. 공식 문서나 기술 근거를 검증하거나, 다른 파일의 용어 동기화, 기술 대안 비교의 충실도, 모든 운영 지표를 독립 심사하지 않는다. 스펙 외 자료가 필요할 정도로 설계가 빠진 경우에는 그 누락과 영향을 스펙 위치에 연결한다. 취향, 문서 서식, 가상의 미래 위험은 finding이 아니다.

중대한 요구사항·설계 누락이나 모순은 blocker/major로 묶어 한 번에 반환한다. 사소한 개선은 minor이며 통과를 막지 않는다. 재리뷰는 수정 부분, 미해결 지적 및 직접 영향받는 관계만 확인하고 무관한 기존 통과 부분을 유지한다.

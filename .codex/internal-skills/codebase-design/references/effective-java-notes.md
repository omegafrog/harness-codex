# Effective Java Notes
## 핵심 원칙

- 공개 범위를 최소화한다.
- 불변성을 기본값으로 둔다.
- 상속보다 컴포지션을 우선한다.
- 타입은 인터페이스로 정의하고, 추상 클래스는 골격 구현에만 쓴다.
- 객체 생성이 복잡하면 정적 팩터리나 빌더를 고려한다.
- 의존성은 직접 생성하지 말고 주입한다.
- public 필드와 가변 전역 상태를 피한다.
- 배열보다 리스트를 우선한다.
- raw type과 불필요한 경고를 남기지 않는다.
- 톱레벨 클래스는 한 파일에 하나만 둔다.
- 상수는 int 대신 enum을 우선한다.

## 적용 방식

- Java 코드를 작성하기 전에 이 문서를 먼저 본다.
- 원본 Obsidian 경로는 이 저장소에서 직접 참조하지 않는다.
- 필요한 경우 이 문서만 갱신해서 유지한다.

# Effective Java 요약

Java 작업에만 참고한다. 이 문서는 설계 결정이 아니다. plan, DDD 설계, 기존 프로젝트 관례가 우선한다.

- 생성: 생성자가 많으면 builder를 고려하고, 의미 있는 생성 경로에는 정적 팩터리를 사용한다. 의존성은 생성자로 주입한다.
- 객체 계약: `equals`를 재정의하면 `hashCode`도 재정의한다. `toString`은 진단에 유용하게 만든다. `clone`보다 복사 생성/팩터리를 선호한다.
- 상태: 변경 가능 상태와 노출을 최소화한다. Value Object는 불변으로 만들고 입력·출력 방어 복사를 고려한다. `finalizer`/`cleaner`에 자원 해제를 맡기지 말고 `try-with-resources`를 쓴다.
- 타입 설계: 상속보다 합성을 우선 검토한다. 구현보다 인터페이스 타입에 의존한다. 상수 집합은 ordinal이 아닌 `enum`과 명시적 필드를 사용한다.
- 제네릭: raw type을 피하고, 경고를 무시하지 말고 원인을 제거한다. 필요 시 한정 와일드카드로 API의 입력/출력 타입을 표현한다. 제네릭 배열과 무분별한 varargs를 피한다.
- 품질: 불필요한 객체 생성과 메모리 참조 보존을 줄인다. 예외·null 처리와 자원 종료를 명확히 검증한다.

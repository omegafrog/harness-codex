## 사용 규칙

- `CONTEXT.md`는 유비쿼터스 언어만 담는다.
- 구현 세부, 계획, 스펙, scratch pad는 넣지 않는다.
- 코드 식별자, 파일 경로, CLI 명령, JSON 키, 프로토콜 이름은 호환이 필요할 때 원형을 유지한다.
- Product Spec에서 정의한 도메인 개념·행위자/역할·업무 상태·규칙 용어는 특정 ticket에 한정하지 않고 프로젝트 공유 vocabulary로 기록한다. 기존 canonical 용어가 같은 의미면 재사용하고 새 개념이면 `CONTEXT.md`에 추가한다.
- 합의된 의미가 바뀌면 기존 정의를 갱신하며, 대체·폐기는 용어 lifecycle을 따른다. UI 문구, 설명용 표현, framework/package/API/code 식별자는 도메인 언어가 아니면 추가하지 않는다.
- 중요한 결정이 생기면 곧바로 ADR로 남긴다.
- 현행 canonical term과 승인된 폐기·대체 기록을 먼저 확인한다. 폐기 용어를 active alias로 다시 등록하지 않는다. 호환 식별자는 경계·근거·제거 조건을 기록해 구분한다.
- 설계에서 개념의 의미·책임·identity·lifecycle이 바뀌면 기존 정의와 비교해 용어 변경을 능동 검토한다. 확정된 모델에 따른 정의 수정·대체·폐기는 사용자 rename 요청 없이 함께 반영하고, 의미가 미확정이면 관련 설계 질문에서 해결한다.

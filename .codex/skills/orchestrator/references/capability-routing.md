# Internal capability routing

Read the matching internal GUIDE and follow its scope. For work that belongs to a Harness workflow, use the workflow route instead.

| User request | Internal GUIDE |
|---|---|
| Diagnose a bug or regression | `.codex/internal-skills/diagnosing-bugs/GUIDE.md` |
| Prevent recurring agent or workflow mistakes | `.codex/internal-skills/correct/GUIDE.md` |
| Maintain or recover a Harness installation | `.codex/internal-skills/harness-maintenance/GUIDE.md` or `.codex/internal-skills/harness-recover/GUIDE.md` |
| Collect engineering sources or assess Harness evaluations | `.codex/internal-skills/knowledge-harvest/GUIDE.md` or `.codex/internal-skills/evaluate-harness/GUIDE.md` |
| Design or implement frontend work | `.codex/internal-skills/frontend-design/GUIDE.md` |
| Review a change or manage its integration pull request | `.codex/internal-skills/code-review/references/repair.md` or `.codex/internal-skills/gh-open-pr/GUIDE.md` |
| Reconcile user-facing verification documentation | `.codex/internal-skills/maintain-verification/GUIDE.md` |
| Run explicit user-journey E2E verification | `.codex/internal-skills/e2e-test/GUIDE.md` |
| Ask focused design questions | `.codex/internal-skills/grilling/GUIDE.md` |
| Explain a topic simply | public `eli5` skill |
| Summarize provided material | `.codex/internal-skills/attention-span/GUIDE.md` |

For internal workflow actions, read their supporting references from the same directory as the GUIDE. Never select a GUIDE solely because a keyword appears; match the requested outcome and current workflow state.

# 유스케이스 문서

## 1. 액터 정의
### 주요 액터
- 플레이어: 재료를 확보하고 무기나 도구를 제작해 판매하면서 시장 독점도를 높이려는 사용자

### 보조 액터
- 브라우저 로컬 저장소: 진행 데이터를 저장하고 복구하는 외부 저장 수단

## 2. 상위 유스케이스 목록
### 플레이어
- UC-01. 플레이어가 싱글 플레이 세션을 시작하거나 이어서 플레이한다.
- UC-02. 플레이어가 던전 탐사를 준비하고 재료를 수집한다.
- UC-03. 플레이어가 수집한 재료로 무기나 도구를 제작한다.
- UC-04. 플레이어가 제작품을 가판대에 진열하고 판매한다.
- UC-05. 플레이어가 창의적 쓰임을 이용해 시장 독점도를 높인다.

## 3. 유스케이스 상세
## UC-01. 플레이어가 싱글 플레이 세션을 시작하거나 이어서 플레이한다
**액터**
- 플레이어

**보조 액터**
- 브라우저 로컬 저장소

**목표**
- 새 게임을 시작하거나 기존 진행 상태를 불러와 핵심 플레이 루프를 이어간다.

**사전조건**
- 게임 클라이언트가 PC 브라우저에서 실행 가능해야 한다.
- 기존 저장 데이터가 있을 수도 있고 없을 수도 있다.

**기본 흐름**
1. 플레이어가 게임에 접속한다.
2. 시스템이 로컬 저장 데이터 존재 여부를 확인한다.
3. 플레이어가 새 게임 시작 또는 이어하기를 선택한다.
4. 시스템이 선택에 맞는 세션 상태를 로드한다.
5. 시스템이 현재 독점도, 보유 재료, 판매 현황, 해금된 던전 정보를 보여준다.

**예외 흐름**
- 저장 데이터가 없으면 시스템은 새 게임 시작만 제공한다.
- 저장 데이터가 손상되었으면 시스템은 직전 정상 저장 스냅샷 복구를 먼저 시도한다.
- 직전 정상 저장 스냅샷도 복구할 수 없으면 시스템은 새 게임 시작만 제공한다.

**결과**
- 플레이어는 유효한 싱글 플레이 세션 상태로 게임을 시작한다.

**비기능 요구사항**
- PC 브라우저 지원
- 로컬 저장 기반 진행 복구
- 최신 저장 스냅샷과 직전 정상 저장 스냅샷 유지
- 게임세션, 인벤토리, 가판대, 시장상태를 하나의 JSON 자동 저장 스냅샷으로 유지

## UC-02. 플레이어가 던전 탐사를 준비하고 재료를 수집한다
**액터**
- 플레이어

**보조 액터**
- 없음

**목표**
- 목표 시장을 뒤흔들 수 있는 새로운 재료를 확보하고, 어떤 특성의 도구가 유용한지 단서를 얻는다.

**사전조건**
- 플레이어가 탐사 가능한 세션 상태여야 한다.
- 최소 1개 이상의 던전이 해금되어 있어야 한다.

**기본 흐름**
1. 플레이어가 던전 후보를 확인한다.
2. 시스템이 던전별 분위기, 위협, 기대 가능한 재료 또는 암시를 보여준다.
3. 플레이어가 모험가 NPC를 고용하거나 동행 구성을 정한다.
4. 플레이어가 던전에 진입한다.
5. 시스템이 탐사 결과로 일반 재료 또는 기괴한 재료를 제공한다.
6. 시스템이 던전 상황을 통해 특정 아이템 특성이 유용할 수 있다는 단서를 제시한다.
7. 플레이어가 획득한 재료를 가지고 마을로 복귀한다.

**예외 흐름**
- 플레이어가 탐사 준비를 완료하지 못하면 던전에 진입하지 못한다.
- 던전 공략에 실패하면 기존 보유 재료는 잃지 않고, 해당 탐사의 보상은 기본 보상 수량의 50%로 축소되며 희귀 재료와 특성 단서는 지급되지 않는다.
- 프로토타입에서는 인벤토리와 재료 보유 한도를 두지 않으므로 초과 재료 처리는 발생하지 않는다.

**결과**
- 플레이어는 제작 가능한 재료와 향후 아이템 설계에 필요한 단서를 확보한다.

**비기능 요구사항**
- 던전별 차별화된 재료/위협 구성
- 재료 특성 데이터 유지
- 프로토타입 범위에 맞는 간결한 탐사 흐름
- 모험가 NPC는 개별 성장 엔티티가 아니라 동행 구성 값으로 처리

## UC-03. 플레이어가 수집한 재료로 무기나 도구를 제작한다
**액터**
- 플레이어

**보조 액터**
- 없음

**목표**
- 재료와 외형을 조합해 시장에서 차별화될 무기나 도구를 만든다.

**사전조건**
- 플레이어가 최소 1개 이상의 제작 재료를 보유해야 한다.
- 제작 가능한 아이템 형태가 해금되어 있어야 한다.

**기본 흐름**
1. 플레이어가 제작 화면에서 사용할 재료를 고른다.
2. 플레이어가 무기나 도구의 외형 또는 형태를 선택한다.
3. 시스템이 재료 조합과 형태를 바탕으로 기본 성능과 특성을 계산한다.
4. 시스템이 제작 결과물의 잠재적 파생 쓰임 해석에 필요한 속성을 정리한다.
5. 플레이어가 결과를 확인하고 제작을 확정한다.

**예외 흐름**
- 재료가 부족하면 시스템은 제작을 진행하지 않는다.
- 조합이 허용되지 않으면 시스템은 이유를 설명하고 다른 선택을 요구한다.
- 유효한 재료 조합과 아이템 형태로 제작을 확정하면 제작은 항상 성공한다.

**결과**
- 플레이어는 판매 또는 활용 가능한 제작품을 획득한다.

**비기능 요구사항**
- 복잡한 수동 제작 절차 없이 결과 확정
- 재료와 형태에 따른 일관된 속성 계산
- 확장 가능한 아이템 조합 구조

## UC-04. 플레이어가 제작품을 가판대에 진열하고 판매한다
**액터**
- 플레이어

**보조 액터**
- 없음

**목표**
- 제작품을 시장에 내놓아 판매 성과와 수요 반응을 얻는다.

**사전조건**
- 플레이어가 최소 1개 이상의 제작품을 보유해야 한다.

**기본 흐름**
1. 플레이어가 대장간 가판대에 올릴 아이템을 선택한다.
2. 시스템이 해당 아이템의 특성, 예상 관심 요소, 현재 시장 분위기를 보여준다.
3. 플레이어가 판매를 시작한다.
4. 시스템이 현재 수요, 경쟁 대장장이 상황, 아이템 특성을 반영해 판매 결과를 계산한다.
5. 시스템이 판매량, 인기 원인, 시장 반응을 플레이어에게 보여준다.

**예외 흐름**
- 판매 중인 슬롯이 3개를 초과하면 시스템은 추가 등록을 막는다.
- 플레이어는 가격을 직접 설정하지 않으며, 시스템은 아이템 속성, 수요, 경쟁 상황을 기준으로 가격을 자동 산정한다.
- 판매 결과 계산에 필요한 창의적 쓰임 해석이 실패하면 시스템은 기본 판매 규칙으로 대체 처리한다.

**결과**
- 플레이어는 금전, 독점도 변화, 시장 피드백을 얻는다. 평판은 프로토타입 범위에서 별도 영속 상태로 관리하지 않는다.
- 판매 완료된 제작품은 활성 인벤토리와 가판대 슬롯에서 제거되고 판매 이력 요약으로 보존된다.

**비기능 요구사항**
- 판매 결과 계산 일관성
- 실패 시 기본 로직으로 폴백
- 수요 변화 원인 추적 가능성
- 판매 결과와 시장 변화는 유스케이스 완료 후 자동 저장
- 자동 저장 실패 시 플레이어에게 저장 실패 알림을 표시하고 도메인 상태는 메모리에 유지

## UC-05. 플레이어가 창의적 쓰임을 이용해 시장 독점도를 높인다
**액터**
- 플레이어

**보조 액터**
- 없음

**목표**
- 아이템의 예상 밖 쓰임을 시장에 퍼뜨려 수요를 폭발시키고 경쟁 대장장이를 앞선다.

**사전조건**
- 플레이어가 독특한 특성을 가진 아이템을 제작 및 판매 가능한 상태여야 한다.
- 시스템이 시장 수요와 경쟁 상태를 계산할 수 있어야 한다.

**기본 흐름**
1. 시스템이 아이템 특성 조합을 바탕으로 본래 용도 외의 창의적 쓰임 후보를 도출한다.
2. 시스템이 규칙 기반 후보 생성 결과를 템플릿 또는 간단한 AI풍 설명으로 정리한다.
3. 시스템이 그 쓰임이 어떤 상황에서 유행하거나 문제 해결에 쓰일지 판단한다.
4. 시스템이 소문, 던전 공략 성공, 생활 편의성, 유행 소비 같은 형태로 수요 상승 이벤트를 발생시킨다.
5. 경쟁 AI 대장장이는 플레이어의 유행 특성을 따라 하거나 카운터 상품을 내며 시장 점유율 경쟁을 수행한다.
6. 플레이어가 수요 상승 원인과 판매 증가를 확인한다.
7. 시스템이 경쟁 대장장이 대비 플레이어의 독점도 또는 시장 지배력을 갱신한다.
8. 플레이어의 독점도가 100에 도달하면 시스템이 프로토타입 승리를 판정한다.

**예외 흐름**
- 도출된 쓰임이 지나치게 모순적이거나 시스템 규칙을 벗어나면 시스템은 다른 후보를 사용하거나 기본 수요 계산으로 되돌린다.
- 창의적 쓰임이 전혀 시장 반응을 얻지 못하면 수요 변화 없이 일반 판매 결과만 반영한다.
- 경쟁 AI가 유행 추종 또는 카운터 상품 생성에 실패하면 시스템은 기본 시장 점유율 경쟁만 수행한다.

**결과**
- 플레이어는 특정 아이템 조합이 왜 성공했는지 이해하고, 다음 제작 전략에 반영할 수 있다.
- 시장 독점도 또는 경쟁 우위 지표가 갱신된다.
- 독점도가 100이면 프로토타입 승리 상태가 된다.
- 창의적 쓰임 해석 결과와 수요 변화 원인은 저장 데이터에 포함되어 이후 불러오기 시 유지된다.

**비기능 요구사항**
- 창의적이고 과장된 결과 허용
- 수요 변화 설명 가능성
- 생성 실패 시 세션 지속성 보장
- 외부 API 없이 동작 가능한 프로토타입
- 창의적 쓰임 결과는 저장하고 불러오기 시 재계산하지 않음

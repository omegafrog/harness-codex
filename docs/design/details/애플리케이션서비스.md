# 애플리케이션 서비스

## 1. 개요
- 입력 유스케이스 문서: docs/design/유스케이스.md
- 입력 이벤트 스토밍 문서: docs/design/이벤트 스토밍.md
- 입력 어그리거트 문서: docs/design/details/어그리거트.md
- 목적: 유스케이스별 흐름을 오케스트레이션하는 애플리케이션 서비스를 정의한다.

## 2. 설계 원칙
- 유스케이스 단위 오케스트레이션: UC-01~UC-05를 각각 하나의 주 서비스가 끝까지 조정한다.
- Repository를 통한 Aggregate 조회/저장: 각 서비스는 필요한 어그리거트를 조회한 뒤 루트 메서드 호출 결과만 저장한다.
- Aggregate Root 메서드 호출: 재료 차감, 판매 슬롯 등록, 독점도 반영은 루트 메서드로만 수행한다.
- 외부 협력 객체/다른 BC 호출: 브라우저 로컬 저장소, 카탈로그 조회, 창의적 쓰임 계산, 시장 반응 계산은 포트 또는 BC 클라이언트로 호출한다.
- 비즈니스 로직 노출 금지: 서비스는 순서, 실패 분기, 저장 타이밍만 조정하고 규칙 판단은 어그리거트/도메인 서비스에 맡긴다.
- 트랜잭션/저장 순서 고려: 상태 변경 성공 후 자동 저장을 수행하고, 해석 실패/경쟁 대응 실패는 폴백 결과를 반영한 뒤 저장한다.
- 프로토타입 통합 방식: BC 간 협력은 이벤트 버스 없이 동일 프로세스 동기 호출로 처리한다.

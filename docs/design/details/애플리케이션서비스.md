# 애플리케이션 서비스

## 1. 애플리케이션 서비스 목록
|애플리케이션 서비스|담당 유스케이스|소속 BC|주요 책임|호출 어그리거트/도메인 서비스|외부 협력/포트|비즈니스 로직 노출 방지 규칙|
|---|---|---|---|---|---|---|
|CalculatorCalculationAppService|UC-01 End user calculates an arithmetic expression|Calculator BC candidate|Receive explicit calculate request, load current session state through repository interface, invoke expression evaluation, apply outcome to aggregate root, save through repository interface, compose displayed result or `ERROR`.|CalculatorSessionAggregate, ExpressionEvaluationService|CalculatorSessionRepository|Must not parse expression inline or decide success/error rules itself; only passes `EvaluationOutcome` into root.|
|CalculatorEditingAppService|UC-02 End user edits the current expression|Calculator BC candidate|Receive expression input/update/delete actions, load current session through repository interface, construct `ExpressionText`, call root edit methods, save through repository interface, return updated expression state.|CalculatorSessionAggregate|CalculatorSessionRepository|Must not directly clear stale result fields; root methods enforce that invariant.|
|CalculatorResetAppService|UC-03 End user clears the calculator state|Calculator BC candidate|Receive clear request, load current session through repository interface, call root reset method, save through repository interface, return empty-state view model.|CalculatorSessionAggregate|CalculatorSessionRepository|Must not blank fields directly; root owns atomic reset.|
|CalculatorRecoveryAppService|UC-04 End user retries calculator use after an app failure|Calculator BC candidate|Receive failure-display or manual-refresh recovery flow trigger, load/init current session through repository interface, call failure or recovery root methods, save through repository interface, return failure or empty state.|CalculatorSessionAggregate|CalculatorSessionRepository|Must not encode recovery state rules itself; root decides failure-visible vs recovered-empty transitions.|

## 2. 유스케이스별 오케스트레이션
|유스케이스|처리 순서|조회/저장 대상|호출하는 도메인 메서드|호출하는 도메인 서비스|외부 협력|결과|
|---|---|---|---|---|---|---|
|UC-01|1. Receive explicit `=`/`Calculate` request. 2. Load current `CalculatorSession` through repository interface. 3. Read current `ExpressionText`. 4. Call `ExpressionEvaluationService`. 5. Pass `EvaluationOutcome` to root. 6. Save updated session through repository interface. 7. Return result or `ERROR` view data.|CalculatorSessionAggregate load/save|`applyCalculationOutcome(outcome)`|`ExpressionEvaluationService.evaluate(expression)`|CalculatorSessionRepository|Successful numeric result formatted for display, or `ERROR`.|
|UC-02|1. Receive character input/change or delete request. 2. Load current `CalculatorSession` through repository interface. 3. For replacement path, create `ExpressionText`. 4. Call root edit method. 5. Save updated session through repository interface. 6. Return updated expression and cleared-result state.|CalculatorSessionAggregate load/save|`replaceExpression(newExpression)` or `deleteLastCharacter()`|None|CalculatorSessionRepository|Updated current expression; any stale result cleared.|
|UC-03|1. Receive `Clear` request. 2. Load current `CalculatorSession` through repository interface. 3. Call root clear method. 4. Save updated session through repository interface. 5. Return empty-state view data.|CalculatorSessionAggregate load/save|`clearState()`|None|CalculatorSessionRepository|Empty calculator state.|
|UC-04|1. On app-load/runtime failure, create or load current session through repository interface and call failure transition. 2. Show failure state. 3. On manual refresh success path, initialize or reload session through repository interface and call recovery transition. 4. Save updated session through repository interface. 5. Return failure or empty-state view data.|CalculatorSessionAggregate load/save or initialize|`markFailureVisible()` and `markRecoveredToEmpty()`|None|CalculatorSessionRepository|Failure state remains, or calculator returns to empty state after successful refresh.|

## 5. 포트 및 외부 협력 후보
|포트/협력 객체|종류|호출 주체|목적|반환/전달 값|관련 유스케이스|비고|
|---|---|---|---|---|---|---|
|CalculatorSessionRepository|Repository interface|All calculator app services|Load/save current page-session aggregate state behind an abstraction separated from application services.|`CalculatorSessionAggregate`|UC-01, UC-02, UC-03, UC-04|Current implementation plan: file-backed repository adapter behind this interface.|
|FileBackedCalculatorSessionRepository|Repository adapter|Infrastructure layer used by all calculator app services via interface binding|Provide current concrete persistence strategy for the repository interface while keeping application-service dependency direction unchanged.|Serialized `CalculatorSessionAggregate` state|UC-01, UC-02, UC-03, UC-04|Concrete implementation detail; app services must not depend on this type directly.|
|ExpressionEvaluationService|Domain service|CalculatorCalculationAppService|Evaluate arithmetic expression with precedence and invalid/incomplete detection.|`EvaluationOutcome`|UC-01|Domain collaboration, not infra port.|
|FailureDetectionInput|Application input boundary|CalculatorRecoveryAppService|Receive app-load/runtime failure signal from UI/runtime layer.|Failure occurrence signal|UC-04|Not an external system; boundary from runtime/UI adapter into app service.|

## 6. 트랜잭션 및 일관성 경계
|유스케이스|트랜잭션 후보|동시에 저장해야 할 Aggregate|외부 호출 분리 필요성|실패/보상 처리|비고|
|---|---|---|---|---|---|
|UC-01|Single local unit around one session update and file-backed save.|CalculatorSessionAggregate only|No external network call; only local domain-service invocation and repository interface save.|If evaluation fails semantically, apply failure outcome and return `ERROR`; no compensation needed.|File-backed save remains within same application-service orchestration boundary.|
|UC-02|Single local unit around one session edit and file-backed save.|CalculatorSessionAggregate only|None|If VO creation rejects disallowed characters, reject request before state mutation.|No cross-aggregate consistency.|
|UC-03|Single local unit around one reset and file-backed save.|CalculatorSessionAggregate only|None|No compensation needed; operation deterministic.|Atomic empty-state reset only.|
|UC-04|Single local unit per failure or recovery transition and file-backed save.|CalculatorSessionAggregate only|None|If refresh attempt fails, remain in failure-visible state; no compensation beyond preserving failure state.|Manual refresh behavior limits orchestration complexity.|

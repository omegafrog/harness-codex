# 도메인 모델

## 1. 개요
- 입력 이벤트 스토밍 문서: docs/design/이벤트 스토밍.md
- 입력 유스케이스 문서: docs/design/유스케이스.md
- 목적: 이벤트, 커맨드, 정책으로부터 엔티티, VO, 도메인 메서드, 도메인 서비스를 도출한다.

## 2. 도출 기준
- 엔티티 기준: 세션, 보유 자산, 탐사 준비, 시장 상태처럼 시간 경과에 따라 동일성을 유지하며 상태 전이가 추적되어야 하는 대상을 엔티티로 본다.
- VO 기준: 독점도, 재료 속성, 동행 구성, 판매 결과처럼 값 자체가 의미를 가지며 생성 시 규칙 검증이 필요한 대상을 VO로 본다.
- 메서드 기준: 자기 상태를 바꾸거나 자기 상태만 검증하는 행동만 엔티티/VO 메서드로 둔다.
- 도메인 서비스 기준: 저장 복구, 탐사 결과 생성, 제작 속성 계산, 창의적 쓰임 해석, 판매 결과 계산처럼 여러 도메인 객체와 규칙 조합이 필요한 행동은 도메인 서비스로 분리한다.

|던전|DungeonId|탐사 대상의 분위기, 위협, 기대 재료, 선호 특성 단서를 정의한다.|분위기, 위협, 기대 재료, 선호 특성 단서, 해금 여부|UC-02 `던전 후보 확인이 요청되었다`, FR-008, FR-008-1|콘텐츠 데이터이지만 탐사 도메인에서는 식별이 중요하다|

|경쟁대장장이|CompetitorId|유행 추종 또는 카운터 상품 대응에 따른 경쟁자별 상태를 유지한다.|전략 성향, 현재 점유율, 최근 대응 결과|UC-05 `경쟁 시장 대응이 반영되었다`, FR-004, FR-006-1|시장상태 내부 엔티티|

## 4. 값 객체
|VO|표현 값|생성 시 검증 규칙|불변성/교체 규칙|사용 위치|도출 근거|
|---|---|---|---|---|---|
|독점도|0 이상 100 이하 지표|0 미만, 100 초과 값은 허용하지 않는다.|증감 시 새 값으로 교체한다.|게임세션, 시장상태|FR-002, FR-005-1, UC-05 `독점도가 갱신되었다`|
|승리상태|진행 중/승리|승리 상태는 독점도 100 도달 근거 없이 생성하지 않는다.|판정 시 새 값으로 교체한다.|게임세션|UC-05 `프로토타입 승리가 판정되었다`|
|저장스냅샷메타|최신/직전 정상 스냅샷의 식별 정보와 정상 여부|스냅샷 종류와 무결성 상태가 함께 있어야 한다.|복구 시 선택된 메타로 교체한다.|게임세션, 세션복구서비스|UC-01 예외 흐름, FR-003-2, NFR-018|
|해금던전집합|현재 해금된 DungeonId 목록|중복 ID를 허용하지 않는다.|해금 변동 시 전체 집합을 교체한다.|게임세션, 탐사준비|UC-01 `해금 던전 정보`, UC-02 사전조건|
|동행구성|모험가 NPC 선택 결과|빈 구성은 준비 완료 상태로 볼 수 있는지 입력 규칙에 맞게 판정 가능해야 한다.|구성 변경 시 새 값으로 교체한다.|탐사준비|UC-02 `모험가 동행 구성을 확정한다`, FR-007|
|탐사보상|획득 재료 목록, 희귀 여부, 기본/실패 배수|실패 보상은 기본 보상의 50%만 허용하고 희귀 재료를 포함할 수 없다.|탐사 결과마다 새 값으로 생성한다.|탐사준비, 인벤토리|UC-02 `재료가 획득되었고 단서가 제시되었다`, FR-011-1|
|탐사단서|특정 상황에서 유용한 특성 설명|실패 보상과 함께 생성될 수 없고 설명 텍스트가 비어 있으면 안 된다.|획득 시 새 값으로 추가한다.|던전, 게임세션 또는 시장상태 요약|UC-02 `단서가 제시되었다`, FR-011|
|재료속성|강도, 경도, 길이 영향, 냄새, 유기성, 희귀성, 기괴함|속성 값은 정의된 범위와 타입을 만족해야 한다.|속성 변경 대신 새 값으로 교체한다.|제작품, 인벤토리, 제작속성계산서비스|FR-010|
|재료수량|재료별 보유 수량|음수 수량을 허용하지 않는다.|증감 시 새 값으로 교체한다.|인벤토리|UC-02/03, NFR-006|
|아이템형태|무기/도구 형태 식별과 기본 제약|해금되지 않은 형태나 허용되지 않은 형태 코드는 생성하지 않는다.|선택 변경 시 새 값으로 교체한다.|제작품, 제작속성계산서비스|UC-03, FR-012-1|
|제작속성|기본 성능과 특성 계산 결과|유효한 재료 조합과 아이템 형태에서만 생성 가능하다.|재계산 시 새 값으로 교체한다.|제작품, 판매/시장지배력 BC 요약|UC-03 `제작 속성이 계산되었다`, FR-014|
|파생쓰임해석입력|창의적 쓰임 해석에 필요한 정규화된 속성 묶음|제작속성 없이 생성할 수 없다.|제작 결과 확정 시 함께 고정한다.|제작품, 창의적쓰임해석서비스|UC-03 `제작 결과 후보가 구성되었다`, FR-015|
|창의적쓰임후보|예상 밖 쓰임 설명, 유효성, 예상 수요 효과|설명과 쓰임 분류가 있어야 하며 무효 후보는 유효 후보와 같은 구조로 저장하지 않는다.|후보 교체 또는 폴백 시 새 값으로 교체한다.|시장상태, 판매 결과 계산|UC-05 `창의적 쓰임 후보가 도출되었다`, FR-016, FR-017|
|수요변화원인|유행, 문제 해결, 소문 확산 등 수요 상승 이유|원인 분류와 플레이어 설명 문자열이 함께 있어야 한다.|발생 때마다 새 값으로 생성한다.|시장상태, 게임세션|UC-04 `인기 원인`, UC-05 `수요 상승 이벤트가 발생하였다`, FR-019|
|판매결과|판매량, 금전 변화, 독점도 변화, 인기 원인, 경쟁 변화|판매량과 금전 변화는 같은 계산 기준으로 생성되어야 한다.|판매마다 새 값으로 생성한다.|가판대, 시장상태, 게임세션|UC-04 `판매 결과가 계산되었다`, FR-021, FR-025|
|가격정보|시스템 자동 산정 가격과 근거 요약|플레이어 입력 가격을 포함할 수 없다.|시장 조건 변화 시 새 값으로 교체한다.|가판대, 판매 준비 화면|UC-04 `시스템 산정 가격`, FR-024|

## 5. 도메인 메서드
|소유 모델|메서드|행동|상태 변경/검증|도출 근거|내부 메서드 판단|
|---|---|---|---|---|---|
|게임세션|startNew(initialUnlockedDungeons, initialMoney)|새 게임 세션을 시작한다.|초기 독점도, 승리 상태, 해금 던전, 금전을 초기화한다.|UC-01 `새 게임 시작`, FR-001|세션 자신의 초기 상태만 바꾸므로 내부 메서드로 둔다.|
|게임세션|restore(snapshotSummary)|복구된 스냅샷 요약으로 세션 상태를 반영한다.|저장 기준이 같은 상태 묶음으로 교체한다.|UC-01 `세션 상태가 로드되었다`, 규칙 `동일한 저장 기준으로 함께 로드`|외부 저장소 조회는 하지 않고 결과 값만 받으므로 내부 메서드로 둔다.|
|게임세션|applyMarketOutcome(salesMoney, monopolyDelta, demandReason)|판매 및 시장 반응 결과를 세션에 반영한다.|보유 금전, 독점도, 마지막 반영 원인을 변경한다.|UC-04 결과, UC-05 `독점도가 갱신되었다`|세션 자신의 값만 반영한다.|
|게임세션|declareVictoryIfReached()|독점도 100 도달 시 승리 상태를 확정한다.|승리 상태를 변경하거나 유지한다.|UC-05 `프로토타입 승리가 판정되었다`, FR-005-1|독점도와 승리 상태만 검증하므로 내부 메서드다.|
|인벤토리|applyExplorationReward(reward, clues)|탐사 결과를 자산에 반영한다.|재료 수량을 늘리고 탐사 단서를 저장 대상 요약에 추가한다.|UC-02 `탐사 결과가 세션에 반영되었다`|자신의 재고와 보유 정보만 바꾸므로 내부 메서드다.|
|인벤토리|canCraft(materialCost)|제작 가능 여부를 검증한다.|재료 부족 여부를 판정한다.|UC-03 `제작 가능 여부 검증이 요청되었다`, FR-015-2|인벤토리 자신의 재고만 검증하므로 내부 메서드다.|
|인벤토리|confirmCraft(materialCost, craftedItem)|재료를 소비하고 제작품을 추가한다.|재료 수량 차감과 제작품 추가를 동시에 반영한다.|UC-03 `제작품이 획득되었다`, 규칙 `재료 소비와 제작품 추가는 동일 상태 변경`|자신의 상태만 바꾸므로 내부 메서드다.|
|인벤토리|reserveForSale(craftedItemId)|판매 시작 전에 제작품을 판매 예약 상태로 둔다.|제작품 소유 상태를 판매 예약으로 변경한다.|UC-04 `판매할 제작품을 진열한다`|인벤토리 내부 소유 상태만 바꾼다.|

|탐사준비|approveEntry(unlockedDungeons)|해금 상태와 준비 완료 여부를 검증해 진입을 승인한다.|거부 사유 또는 승인 상태를 변경한다.|UC-02 `던전 진입이 승인되었다`, `던전 진입이 거부되었다`|외부 시스템 없이 자신의 준비 상태와 전달받은 값만 검증한다.|

## 8. 확정 결정
- 모험가 NPC는 프로토타입 범위에서 개별 엔티티로 관리하지 않고 `동행구성` VO로만 설계한다.
- 금전은 정수 단위 골드로 표현하며 판매 보상 누적 외의 지출 경제는 구현하지 않는다.

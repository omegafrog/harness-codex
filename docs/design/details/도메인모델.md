# 도메인 모델

## 1. 엔티티
|엔티티|식별자|책임|주요 상태|도출 근거|비고|
|---|---|---|---|---|---|
|CalculatorSession|sessionId|Own the current calculator state for one page session, accept expression edits, execute explicit calculation, clear state, and transition into failure or error-visible states.|currentExpression, currentResult, visibleStatus, failureStatus|UC-01 result/preconditions, UC-02 main flow/result, UC-03 main flow/result, UC-04 main/exception flow, FR-007 to FR-016, NFR-003|Single end-user, frontend-only, in-memory lifecycle root candidate for later aggregate design.|

## 2. 값 객체
|VO|표현 값|생성 시 검증 규칙|불변성/교체 규칙|사용 위치|도출 근거|
|---|---|---|---|---|---|
|ExpressionText|Raw arithmetic expression string|Only characters allowed by scope: digits, whitespace if permitted by UI, `+`, `-`, `*`, `/`, `.`, `(`, `)`; keep exactly as entered when invalid or incomplete; no auto-correction.|Replace whole value on every edit/delete/clear.|CalculatorSession.currentExpression|UC-01 step 1, UC-02 main/exception flow, FR-002 to FR-006, FR-008, FR-014|
|CalculationResult|Displayed numeric result|Must represent a successful evaluated numeric value; long decimal display normalized to 10 decimal places when formatting is required.|Immutable; replaced after each successful calculation; removed when expression changes or clear occurs.|CalculatorSession.currentResult|UC-01 result, FR-010, FR-011|
|DisplayStatus|Current user-visible state|Must be one of `EMPTY`, `EDITING`, `RESULT_VISIBLE`, `ERROR_VISIBLE`, `FAILURE_VISIBLE`.|Replace on each state transition.|CalculatorSession.visibleStatus|UC-01 result/exception, UC-02 result, UC-03 result, UC-04 result/exception, FR-012, FR-013, FR-015, FR-016|
|EvaluationOutcome|Result of expression evaluation passed into domain behavior|Must contain either a successful numeric value or an evaluation failure reason; cannot contain both.|Created per calculation attempt, consumed by CalculatorSession, then discarded.|Input to CalculatorSession.applyCalculationOutcome(...)|UC-01 success/failure result, FR-009 to FR-013|
|FailureState|App runtime/load failure visibility state|Represents whether calculator is operational or in manual-refresh-required failure mode.|Replace on load recovery attempt outcome.|CalculatorSession.failureStatus|UC-04 preconditions/main flow/result, FR-016, NFR-011|

## 3. 도메인 메서드
|소유 모델|메서드|행동|상태 변경/검증|도출 근거|내부 메서드 판단|
|---|---|---|---|---|---|
|CalculatorSession|replaceExpression(newExpression: ExpressionText)|Replace the current expression with exactly entered content.|Updates currentExpression; if currentResult exists, clears it; sets visibleStatus to `EMPTY` or `EDITING`.|UC-02 step 1/3/4, FR-011|Changes only session-owned state.|
|CalculatorSession|deleteLastCharacter()|Apply single-character delete/backspace to current expression.|Replaces currentExpression with one-character-shorter value; clears currentResult when expression changes.|UC-02 step 2/3/4, FR-008, FR-011|Changes only session-owned state.|
|CalculatorSession|applyCalculationOutcome(outcome: EvaluationOutcome)|Reflect explicit calculation result already computed elsewhere.|On success, sets currentResult and `RESULT_VISIBLE`; on failure, clears/stops result display and sets `ERROR_VISIBLE`.|UC-01 step 2-5, exception/result, FR-009 to FR-013|Session does not call evaluator itself; no external/domain collaboration embedded.|
|CalculatorSession|clearState()|Reset calculator to empty state.|Removes currentExpression and currentResult; sets visibleStatus to `EMPTY`; clears failure-visible state if present.|UC-03 main flow/result, FR-007, FR-015|Changes only session-owned state.|
|CalculatorSession|markFailureVisible()|Transition session into simple failure state after app-load/runtime failure.|Sets failureStatus and visibleStatus to failure-visible form; clears normal calculation result visibility.|UC-04 preconditions/main flow, FR-016, NFR-011|Own state transition only.|
|CalculatorSession|markRecoveredToEmpty()|Return recovered app to empty calculator state after successful manual refresh.|Resets expression/result and sets visibleStatus to `EMPTY`; clears failureStatus.|UC-04 main/result, FR-015, FR-016|Own state transition only.|
|ExpressionText|validateAllowedCharacters()|Validate expression contains only in-scope tokens.|Rejects creation when disallowed characters appear.|FR-003 to FR-005|Validation belongs to VO itself.|
|CalculationResult|formatForDisplay()|Produce normalized display value for numeric result.|Ensures long decimal outputs use 10 decimal places when needed.|UC-01 result, FR-010|Formatting rule belongs to result value itself.|
|EvaluationOutcome|isSuccess()|Expose whether calculation succeeded.|Validation-only helper for outcome branching.|UC-01 result/exception|Pure self-inspection.|

## 6. 도메인 서비스 후보
|도메인 서비스|책임|필요한 협력 객체/값|왜 모델 내부 메서드가 아닌가|관련 유스케이스|도출 근거|
|---|---|---|---|---|---|
|ExpressionEvaluationService|Evaluate a full arithmetic expression with precedence and return EvaluationOutcome.|ExpressionText input; arithmetic evaluation rules for precedence, decimal, parentheses, invalid-operation detection.|Evaluation uses parsing/evaluation logic over expression content rather than mutating one entity/VO's own state; CalculatorSession should receive outcome, not embed evaluator complexity.|UC-01|UC-01 step 3, FR-006, FR-009, FR-012, FR-013, NFR-001|

## 7. 도메인 규칙
|규칙|적용 모델|검증 시점|위반 시 결과|도출 근거|
|---|---|---|---|---|
|Calculation executes only on explicit `=` or `Calculate` action.|CalculatorSession, ExpressionEvaluationService|Before evaluation is requested/applied.|No automatic evaluation; session state remains editing-only until explicit trigger.|FR-009, UC-01 step 2|
|Expression must not be auto-corrected when invalid or incomplete.|ExpressionText, CalculatorSession|During edit and failed calculation handling.|Keep entered expression as-is; show `ERROR` only after explicit calculation failure.|UC-01 exception flow, UC-02 exception flow, FR-014|
|Invalid operation, syntactically invalid expression, or incomplete expression yields `ERROR`.|EvaluationOutcome, CalculatorSession|When calculation outcome is applied.|visibleStatus becomes `ERROR_VISIBLE`; no successful result shown.|UC-01 exception/result, FR-012, FR-013|
|Any expression change after a shown result clears the old result immediately.|CalculatorSession|On replaceExpression/deleteLastCharacter.|currentResult removed before next calculation.|UC-02 step 4, FR-011|
|Clear resets both expression and result to empty in-memory state.|CalculatorSession|On clearState().|Session returns to `EMPTY` state.|UC-03, FR-007, FR-015|
|Recovered app starts from empty state after successful manual refresh.|CalculatorSession|On markRecoveredToEmpty().|No prior expression/result survives recovery.|UC-04 result, FR-015, FR-016, NFR-011|
|Calculator state exists only in current page-session memory.|CalculatorSession|Throughout lifecycle.|No persistence or cross-session restoration behavior allowed in model.|UC-02 NFR, UC-03 NFR, NFR-003, NFR-004|

## 8. 확인 필요
- Whether `ExpressionText` should preserve or normalize whitespace. Requirements do not explicitly define whitespace handling.
- Whether an empty expression is represented as an empty string VO or as absence of `ExpressionText` on `CalculatorSession`.
- Whether `FailureState` should remain a separate VO or collapse into `DisplayStatus` only. Current design keeps it explicit because UC-04 distinguishes failure/recovery behavior from normal editing/calculation flow.
- Detailed event/command/policy names from per-use-case event-storming slice documents were not available under current read limits, so traceability is grounded in the canonical event-storming index plus use cases and requirements.

# 바운디드 컨텍스트

## 1. 개요
- 입력 이벤트 스토밍 문서: docs/design/이벤트 스토밍.md
- 목적: 변경 전파 범위와 같은 용어의 다른 모델 표현 여부를 기준으로 BC를 정의한다.

## 2. 경계 결정 기준
- 같은 도메인 용어가 다른 모델로 표현되는 경우: `제작품/아이템`은 보유 자산 모델, 판매 대상 모델, 시장 반응 유발 요인 모델로 의미가 달라진다.
- 규칙 변경 시점이 다른 경우: 세션 복구 규칙, 탐사 준비 규칙, 제작 조합 규칙, 판매 슬롯 규칙, 시장 지배력 규칙은 서로 다른 시점에 바뀐다.
- 함께 변경되어야 하는 규칙: 독점도와 승리 판정, 수요 변화와 경쟁 대응, 재료 차감과 제작품 추가는 각각 함께 바뀌어야 한다.
- 외부 협력 또는 통합 경계: 브라우저 로컬 저장소는 세션/보유자산 BC의 외부 경계이며, 나머지 BC 간 통합은 단일 플레이 순차 흐름에 맞춘 동일 프로세스 동기 호출로 본다.

## 3. BC 목록
|BC|책임|소유 어그리거트|소유 도메인 모델|주요 유스케이스|경계 결정 이유|
|---|---|---|---|---|---|
|세션/보유자산 BC|세션 시작/복구, 자동 저장 기준, 재료와 제작품 소유 상태, 독점도와 승리 상태를 관리한다.|게임세션 어그리거트, 인벤토리 어그리거트|게임세션, 인벤토리, 제작품, 독점도, 승리상태, 저장스냅샷메타|UC-01, UC-03 결과 반영, UC-04 결과 반영, UC-05 승리 반영|세션 수명주기와 자산 소유 모델은 같은 저장 경계와 같은 사용자 의미를 가진다.|
|탐사 BC|던전 후보 제시, 동행 구성, 진입 승인, 탐사 결과 생성 규칙을 관리한다.|탐사준비 어그리거트|탐사준비, 던전, 동행구성, 탐사보상, 탐사단서|UC-02|`던전`, `위협`, `단서`는 탐사 흐름에서만 일관된 의미를 갖고 제작/판매 규칙과 변경 주기가 다르다.|
|제작 BC|재료와 형태 조합의 유효성 검증, 제작속성 계산, 파생 쓰임 입력 생성 규칙을 관리한다.|없음(도메인 서비스 중심)|제작속성, 아이템형태, 파생쓰임해석입력, 제작속성계산서비스|UC-03|`재료 조합`과 `아이템 형태`는 제작 시점의 의미가 강하고 판매/시장 단계의 가격/수요 규칙과 분리된다.|
|판매 BC|가판대 슬롯 관리, 판매 대상 등록, 판매 시작/피드백 표시의 원천 결과를 관리한다.|가판대 어그리거트|가판대, 판매슬롯, 가격정보, 판매결과|UC-04|`판매 중 슬롯`, `진열`, `판매 결과`는 판매 운영 모델이며 시장 지배력 계산의 내부 규칙과는 다른 경계를 가진다. 화면 문구와 배치는 프레젠테이션 모델에서 변환한다.|
|시장지배력 BC|창의적 쓰임 해석, 수요 변화, 경쟁 대응, 독점도 변화 근거를 관리한다.|시장상태 어그리거트|시장상태, 경쟁대장장이, 창의적쓰임후보, 수요변화원인, 판매결과, 창의적쓰임해석서비스, 경쟁시장대응서비스, 시장지배력갱신서비스|UC-04 계산, UC-05|`시장`, `수요`, `경쟁`, `독점도` 규칙은 함께 변경되어야 하며 판매 운영과 다른 용어 의미를 가진다.|

## 4. BC별 입출력
|BC|수신 커맨드|발행 이벤트|외부 의존|제공 기능|비고|
|---|---|---|---|---|---|
|세션/보유자산 BC|`세션 시작 방식을 선택한다`, `새 게임 시작 또는 이어하기를 선택한다`, 제작/판매/시장 반영 요청|`세션 상태가 로드되었다`, `플레이 가능 세션 상태가 표시되었다`, `제작품이 획득되었다`, `프로토타입 승리가 판정되었다`|브라우저 로컬 저장소|세션 복구, 자산 보유 상태 유지, 승리 상태 유지|외부 시스템 의존이 있는 유일한 BC|
|탐사 BC|`던전 탐사를 준비한다`, `모험가 동행 구성을 확정한다`, `던전에 진입한다`|`탐사 준비가 확정되었다`, `던전 진입이 승인되었다`, `재료가 획득되었고 단서가 제시되었다`, `실패 결과가 반영되었다`|없음|탐사 준비 검증, 탐사 결과 생성|자산 반영은 세션/보유자산 BC에 위임|
|제작 BC|`제작할 재료와 형태를 선택한다`, `제작을 확정한다`|`제작 속성이 계산되었다`, `제작 결과 후보가 구성되었다`, `조합 불가 사유가 표시되었다`|없음|제작 조합 검증, 제작 후보 계산|제작품 소유 상태 변경은 세션/보유자산 BC가 담당|
|판매 BC|`판매할 제작품을 진열한다`, `판매를 시작한다`, `추가 상품을 등록한다`|`판매 준비 정보가 표시되었다`, `판매 피드백이 표시되었다`, `판매 등록이 거부되었다`|시장지배력 BC|슬롯 관리, 판매 요청, 피드백 표시|가격과 판매 계산은 시장지배력 BC 협력 필요|
|시장지배력 BC|`창의적 쓰임 해석을 수행한다`, `시장 반응 계산을 진행한다`, `경쟁 대응을 계산한다`|`판매 결과가 계산되었다`, `기본 판매 결과가 계산되었다`, `수요 상승 이벤트가 발생하였다`, `경쟁 시장 대응이 반영되었다`, `독점도가 갱신되었다`|없음|창의적 쓰임 해석, 수요/경쟁/독점도 계산|외부 API 없이 규칙 기반 동작|

|From BC|To BC|트리거 유스케이스|커뮤니케이션 내용|방식 후보|경계 보호 규칙|
|---|---|---|---|---|---|
|탐사 BC|세션/보유자산 BC|UC-02|해금 던전 조회, 탐사 보상/단서 반영 요청|동일 프로세스 동기 클라이언트 호출|탐사 BC는 인벤토리 내부 컬렉션을 직접 수정하지 않는다.|

|판매 BC|세션/보유자산 BC|UC-04|판매 대상 제작품 조회, 판매 예약/완료 반영 요청|동일 프로세스 동기 클라이언트 호출|가판대는 제작품 엔티티를 직접 수정하지 않고 ID와 요약만 사용한다.|
|판매 BC|시장지배력 BC|UC-04|가격정보 조회, 판매 결과 계산, 창의적 쓰임 실패 시 폴백 계산 요청|동일 프로세스 동기 클라이언트 호출|판매 BC는 수요/경쟁 계산 규칙을 복제하지 않는다.|
|시장지배력 BC|세션/보유자산 BC|UC-05|독점도 변화량과 승리 판정 반영 요청|동일 프로세스 동기 클라이언트 호출|시장지배력 BC는 게임세션 내부 독점도 값을 직접 바꾸지 않는다.|

## 6. 확정 결정
- `세션/보유자산 BC`와 `시장지배력 BC` 사이의 독점도 변경은 프로토타입에서 동일 프로세스 동기 호출로 처리한다.
- 판매 피드백의 원천 데이터는 판매 BC의 도메인 결과로 유지하고, 화면 표시용 문구와 배치는 프레젠테이션 모델에서 변환한다.

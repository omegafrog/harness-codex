# 어그리거트

## 1. 개요
- 입력 도메인 모델 문서: docs/design/details/도메인모델.md
- 목적: 원자적으로 변경되어야 하는 엔티티/VO 경계와 aggregate root를 정의한다.

## 2. 어그리거트 설계 원칙
- 원자적 변경 경계: 같은 규칙을 지키기 위해 동시에 성공하거나 실패해야 하는 상태만 한 어그리거트에 둔다.
- 루트 엔티티 접근: 외부 코드는 루트 엔티티 메서드로만 상태를 바꾼다.
- setter 금지: 상태 변경은 의미 있는 루트 메서드로만 수행한다.
- 외부 협력 금지: 저장소, 규칙 엔진, 다른 BC 호출은 애플리케이션 서비스나 도메인 서비스가 담당한다.

|관계|참조 방식|직접 수정 가능 여부|조정 주체|관련 유스케이스|비고|

|시장상태 어그리거트 -> 게임세션 어그리거트|독점도 변화량과 원인 값 전달|불가|시장지배력애플리케이션서비스|UC-05|독점도와 승리 판정은 게임세션 루트가 수행한다.|

## 7. 확정 결정
- 자동 저장은 게임세션, 인벤토리, 가판대, 시장상태를 하나의 JSON 스냅샷 문서로 묶어 브라우저 로컬 저장소에 저장한다.
- 판매 완료된 제작품은 활성 인벤토리와 가판대 슬롯에서 제거하고 판매 이력 요약으로 보존한다.

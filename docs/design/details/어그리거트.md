# 어그리거트

## 1. 어그리거트 목록
|어그리거트|루트 엔티티|포함 엔티티/VO|책임|원자적 변경 규칙|도출 근거|
|---|---|---|---|---|---|
|CalculatorSessionAggregate|CalculatorSession|ExpressionText, CalculationResult, DisplayStatus, EvaluationOutcome (input-only), FailureState|Own one in-memory calculator session, keep expression/result/display/failure transitions consistent, and enforce reset/error/recovery rules.|Expression change and result clearing happen together; calculation outcome and visible status change together; clear removes expression and result together; recovery resets all visible calculator state together.|UC-01 to UC-04, FR-007 to FR-016, NFR-003, approved 도메인모델.md|

## 2. 루트 메서드
|어그리거트|루트 메서드|변경 대상|검증 규칙|발생/반영 이벤트|관련 유스케이스|
|---|---|---|---|---|---|
|CalculatorSessionAggregate|replaceExpression(newExpression: ExpressionText)|currentExpression, currentResult, visibleStatus|Accept only valid `ExpressionText` tokens; do not auto-correct; if result is visible, clear it immediately.|Reflects expression changed / result cleared behavior from event-storming summary.|UC-02|
|CalculatorSessionAggregate|deleteLastCharacter()|currentExpression, currentResult, visibleStatus|Delete one character only; if expression changes after result visibility, clear result immediately.|Reflects single-character delete/backspace behavior.|UC-02|
|CalculatorSessionAggregate|applyCalculationOutcome(outcome: EvaluationOutcome)|currentResult, visibleStatus|Calculation must have been explicitly triggered outside aggregate; success stores formatted result; failure shows `ERROR`.|Reflects calculation succeeded / calculation failed behavior.|UC-01|
|CalculatorSessionAggregate|clearState()|currentExpression, currentResult, visibleStatus, failureStatus|Always reset to empty in-memory state; no partial clear allowed.|Reflects clear requested / calculator state cleared behavior.|UC-03|
|CalculatorSessionAggregate|markFailureVisible()|failureStatus, visibleStatus, currentResult|Failure state becomes visible; normal result visibility cannot remain active simultaneously.|Reflects app failure shown behavior.|UC-04|
|CalculatorSessionAggregate|markRecoveredToEmpty()|currentExpression, currentResult, visibleStatus, failureStatus|Successful manual refresh recovery must restart from empty state; no previous session state survives.|Reflects refresh recovery succeeded behavior.|UC-04|

## 3. 어그리거트 간 관계
|관계|참조 방식|직접 수정 가능 여부|조정 주체|관련 유스케이스|비고|

## 4. 불변식
|어그리거트|불변식|보장 위치|위반 시 결과|도출 근거|
|---|---|---|---|---|
|CalculatorSessionAggregate|At most one visible result belongs to the current expression state.|`replaceExpression`, `deleteLastCharacter`, `applyCalculationOutcome`|Old result removed when expression changes; stale result must not remain visible.|UC-02 step 4, FR-011|
|CalculatorSessionAggregate|Error visibility and successful result visibility are mutually exclusive.|`applyCalculationOutcome`|Failed calculation cannot leave success result visible.|UC-01 exception/result, FR-012, FR-013|
|CalculatorSessionAggregate|Failure-visible state and normal calculator interaction state are mutually exclusive.|`markFailureVisible`, `markRecoveredToEmpty`, `clearState`|Failure mode blocks normal visible result/editing state until recovery to empty.|UC-04, FR-016, NFR-011|
|CalculatorSessionAggregate|Clear or recovery resets expression and result together.|`clearState`, `markRecoveredToEmpty`|No partial reset allowed.|UC-03, UC-04, FR-007, FR-015, FR-016|
|CalculatorSessionAggregate|All calculator state remains page-session local only.|Whole aggregate lifecycle|No persistence, carry-over, or shared state behavior allowed inside aggregate.|NFR-003, NFR-004|

## 5. 확인 필요
- Whether `FailureState` should stay as an explicit VO inside the aggregate or be folded into `DisplayStatus` in a later correction. Aggregate boundary does not change either way.
- Whether empty expression should be modeled as absent `ExpressionText` or an empty `ExpressionText` instance. Current aggregate keeps this implementation-neutral.
- Detailed event names were not directly readable from per-UC slice files under current limits, so event references stay at summary-name level.

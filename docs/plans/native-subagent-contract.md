# Stage 내부 위임 계약 정리 계획

## 목적

오케스트레이터가 stage를 실행하고, stage가 내부 작업을 native subagent에 직접 위임한다. `spec-me`는 자체 작업과 검토가 완료되면 `completed/OK`를 반환하고 다음 stage는 오케스트레이터가 사용자 범위에 따라 선택한다.

## 변경 범위

1. `SUBTASK_REQUIRED`와 `required_subtasks`의 생산·검증·출력 스키마·호출 지침·더 이상 쓰지 않는 dispatch 경로를 조사해 제거한다. 리뷰 요청과 사용자 질문 등 별도의 실제 소비자가 있는 계약은 호출 경로를 확인하고 유지한다.
2. 내부 위임은 기존 부모 Codex 세션 안에서 native subagent로 실행하며, 중단 뒤 같은 부모 대화를 재개해 기록된 위임 결과를 확인한다. 실행 중 프로세스의 중복 재개는 차단한다. 과거 대기 기록이 있으면 성공으로 위장하지 않고 정확한 복구 불가 사유를 반환한다.
3. `spec-me`와 오케스트레이터 지침을 정리해 `to-ticket`이 후속 stage임을 명시한다. stage 완료와 사용자 질문·실제 차단의 반환 경계를 명확히 한다.
4. 관리 자산의 설치·업데이트·Doctor·ignore 경로를 추적한다. 새 설치와 업데이트 소비자에서 계약과 Git 상태를 검증하고, Harness 생성물은 숨기되 프로젝트 소유 파일은 보존한다.
5. 계약 검증, 중단 재개, 사용자 질문, native 위임과 단계 종료를 회귀 검증한다. 기존 데이터나 다른 workflow에 영향이 있으면 범위와 근거를 보고한다.

## 완료 기준

새 실행이 폐기한 반환값을 생성하거나 수용하지 않고, `spec-me`가 `to-ticket`을 내부 작업으로 요청하지 않는다. 설치된 소비자에서도 동일한 계약이 적용되고 필수 검증이 통과해야 한다.

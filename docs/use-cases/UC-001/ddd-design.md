### Modeling Notes
- `Note Explorer`, `Markdown Note Opening`, and `Editor Pane` remain system or orchestration boundaries in slice evidence. This substep models only the entities and value objects needed to express workspace, folder, note, content, and failure identity.
- `WorkspaceRelativePath` is shared by both `NoteFolder` and `MarkdownNote` so hidden, non-Markdown, or out-of-workspace selections cannot become valid domain identities.
- Existing unsaved-change behavior is intentionally not modeled as an entity/value object here. Slice evidence treats it as reused behavior that belongs in later `Behaviors` and `Application Flow` substeps.

## Behaviors
| Owner | Behavior | Signature | Description | Policy Evidence | Event Evidence |
| --- | --- | --- | --- | --- | --- |
| `NoteFolder` | Accept folder expansion selection | `acceptExpansionSelection(selectedPath: WorkspaceRelativePath): Boolean` | Confirms that the current folder entity is the selected expandable target before any child entries become visible. This keeps folder expansion eligibility on the folder identity itself. | `If the selected item is a Note Folder` allows expansion only for folder selections. | `Expand selected Note Folder` -> `Note Folder expansion was requested` -> `Visible child Note Explorer entries were displayed`. |
| `NoteFolder` | Expose visible child entries | `exposeVisibleChildren(visibleChildPaths: WorkspaceRelativePath[]): NoteFolder` | Produces the folder state whose derived child set contains only visible descendants within the same workspace boundary. Hidden or out-of-workspace paths never enter the expanded result. | Explorer invariants require only visible folder and visible `.md` note entries beneath the fixed workspace. | `Visible child Note Explorer entries were displayed` after folder selection passes validation. |
| `MarkdownNote` | Validate visible markdown selection | `isVisibleMarkdownSelection(): Boolean` | Confirms that the selected note entity is both visible and backed by a `.md` entry before open proceeds. The rule stays on the note because it depends on note identity, visibility, and file type. | `If the selected item is a visible Markdown Note`; invalid selections must skip open. | `Markdown Note open was requested` branches either to `Existing unsaved-change behavior was applied` or to `Markdown Note open was skipped`. |
| `MarkdownNote` | Attach opened body | `attachOpenedBody(body: MarkdownBody): MarkdownNote` | Returns the note state that now carries opened content for rendering in the editor pane after all guards succeed. | Opening is allowed only after visible-markdown validation and unsaved-change approval. | `Opened Markdown Note content was displayed in the Editor Pane` is the success outcome for the selected note. |
| `UnsavedChangeGate` | Decide whether current editor state may be replaced | `allowNoteOpening(currentEditor: EditorPaneContentSnapshot): Boolean` | Reused domain service boundary for the application's existing unsaved-change behavior. It decides whether current editor content may be replaced by the selected note. | `If the existing unsaved-change behavior allows note opening` must run after visible-markdown validation and before content replacement. | `Existing unsaved-change behavior was applied` precedes successful display of opened note content. |
| `MarkdownNoteOpeningPolicy` | Evaluate open eligibility | `evaluateOpenEligibility(note: MarkdownNote, currentEditor: EditorPaneContentSnapshot): NoteOpenDecision` | Domain service that combines note-level selection validity with the reused unsaved-change gate and returns whether opening may continue, be skipped, or fail into preservation handling. | Combines `If the selected item is a visible Markdown Note`, `If the selected item is not a visible Markdown Note`, and `If the existing unsaved-change behavior allows note opening`. | Event storming shows one open request branching into skip, success, or failure paths from the same decision point. |
| `EditorPaneContentSnapshot` | Preserve current content on open failure | `preserveOnOpenFailure(error: NoteOpenError): EditorPaneContentSnapshot` | Keeps the current editor snapshot unchanged when note opening fails, while associating failure context for downstream user feedback. | `If Markdown Note opening fails` requires the current editor content to remain unchanged. | `Markdown Note open failure was produced` -> `Current Editor Pane content was preserved` -> `Error message was displayed to the Note Author`. |

### Behavior Notes
- `UnsavedChangeGate` is modeled as reused domain behavior, not a new entity, because the slice explicitly says the application already has this behavior and UC-001 only needs its allow/deny decision.
- `MarkdownNoteOpeningPolicy` stays at domain-service level because the decision crosses `MarkdownNote` state and current `EditorPaneContentSnapshot`; pushing that coordination into either entity would mix responsibilities.

# 아키텍처 원칙

## 1. 원칙

- 용어는 문서에서 먼저 고정하고 코드가 그 용어를 따른다.
- 사실, 결정, 계획, 실행 결과를 한 문서에 섞지 않는다.
- 코드 조사 없이 사용자 목표를 정리하는 단계와 코드 조사를 포함하는 단계를 분리한다.
- 안정적인 결정은 ADR로 남기고, 임시 판단은 계획에만 둔다.
- ADR은 짧아도 된다. 필요한 경우에만 만들고, 결정과 이유만 적는다.
- 구현은 계획을 따른다. 계획은 설계를 대체하지 않는다.
- 상태와 증거는 구분한다. 상태 문서는 재개와 게이트 판단만 담당한다.
- 새 경계를 만들기 전에 기존 경계가 충분한지 먼저 확인한다.

## 2. 금지 사항

- 기술 계층을 Bounded Context로 취급하지 않는다.
- 구현 절차를 persistent guidance 문서에 넣지 않는다.
- 동일한 결정을 여러 문서에 중복해서 정의하지 않는다.

## 3. 적용

- `CONTEXT.md`는 용어 기준점이다.
- `CONTEXT-MAP.md`는 경계 기준점이다.
- ADR은 결정 기준점이다.
- `docs/architecture/principles.md`는 해석 기준점이다.
